# Security policy

## Reporting a vulnerability

Please do not post exploit instructions, credentials, tokens, personal data, or other sensitive details in a public issue.

If the affected repository offers GitHub Private Vulnerability Reporting or a Security Advisory workflow, use that private channel. Otherwise, contact the maintainer privately through the GitHub profile and share only the details needed to assess the issue.

Please include, where possible:

- affected repository, version, or commit;
- impact and prerequisites;
- minimal reproduction steps using a system you own or are authorized to test;
- sanitized logs and relevant environment details.

Do not test against accounts or systems without permission, and do not upload real user credentials or private data as proof.

## Safe use of projects

Review source code, setup scripts, dependencies, and requested permissions before running a project. Use least privilege and test in an isolated environment when appropriate. Never place production secrets in issue reports, examples, or committed files.

## Scope

Each repository may have its own supported versions and scope. Third-party dependencies and upstream projects have their own security reporting channels. This policy is guidance for responsible reporting, not a promise of a response time or a guarantee that every issue can be fixed.
