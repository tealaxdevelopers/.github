# Contributing to Tealax projects

Thanks for taking the time to contribute. Each repository may have additional instructions; follow those first.

## Before opening an issue or pull request

- Search existing issues and pull requests to avoid duplicates.
- Describe the problem, expected behavior, and steps to reproduce it.
- Keep each change focused and explain why it is useful.
- Add or update tests and documentation where appropriate. If you could not run checks, say so.
- Never commit passwords, API keys, access tokens, private URLs, personal data, or unsanitized logs.

## Source code, assets, and licenses

Only submit material you created or are authorized to redistribute. Preserve existing copyright notices and license terms. When adapting third-party code, assets, documentation, or generated output, record the upstream source and verify its license and redistribution conditions.

Do not submit leaked private material, proprietary code, or decompiled/reconstructed code unless you have verified that you have the right to publish it. A license file added to a repository does not grant rights to material whose ownership or origin is unclear. AI-generated contributions should be reviewed for correctness, security, and possible copied or incompatible material before submission.

## Security-sensitive changes

Do not contribute credential collection, unauthorized access, evasion, or features intended to harm users or third-party systems. Security testing must be limited to systems you own or are explicitly authorized to assess. Report suspected vulnerabilities privately as described in `SECURITY.md`.

## Review

Maintainers may request additional tests, documentation, provenance details, or licensing clarification. Contributions may be declined when source rights, safety, or technical behavior cannot be established.
